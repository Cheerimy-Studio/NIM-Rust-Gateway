# 独立上游接口更新与安全复核

本次更新基于上一轮已交付的 16 测试修复版本，包含此前的修复，不回退到最初仓库代码。GitHub 原始基线为 `2231279e64ed6f3a5d0f74c509c8a7ca9de482a0`。完整补丁和只包含本轮更新的增量补丁分别提供。

## 使用方式

1. 管理后台进入「上游」，编辑渠道。
2. Base URL 填 API 公共前缀，如 `https://api.example.com/v1`。
3. 「发送到上游的接口」选择 Chat Completions、Responses、Anthropic Messages 或文本 Completions。
4. 「上游鉴权」选择自动、Bearer 或 X-API-Key，保存。

明确选择的上游接口不由下游路径决定。例如下游 `/v1/chat/completions` 可以实际发送到上游 `/responses`；下游 `/v1/messages` 也可以发到上游 `/chat/completions`。请求、非流式响应和 SSE 流式事件均转换。

旧配置缺失 `api_endpoint` 或选择 `auto` 时保留旧行为，避免升级改变既有流量。向量接口独立使用 `/embeddings`。

## 实现

- `src/bridge.rs` 集中处理上游协议选择、请求转换、JSON 响应转换、原生 SSE 转换、鉴权和有界响应读取，供两个代理入口复用。
- `src/upstreams.rs` 验证并保存 `api_endpoint` / `auth_mode`。局部启停更新保留已有字段；路由变化会失效旧缓存。
- `web/admin.html` / `web/admin.js` 提供编辑、回填、保存、列表展示与统一表单重置。选择普通限速预设不会重置已选接口。
- 固定参数在选定上游协议转换后应用，使用上游字段名。模型和流式模式由网关控制，避免固定参数造成计费模型或响应模式不一致。
- 模型别名、成功计费、账号释放及已有错误处理继续使用网关内部路径。

## 修复的风险与问题

| 问题 | 修复 |
|---|---|
| 下游路径直接决定上游路径 | 渠道显式选择上游协议，转换完整载荷和事件 |
| 仅更换 URL 导致请求/响应结构不匹配 | 双向适配文本、工具、图片、结束原因与 usage |
| 重试时渠道固定参数串到其他渠道 | 每次从干净请求构造；固定参数只应用于当前上游 |
| 后台和用户中心把 Cookie 本身当作 CSRF 证明 | 强制独立 X-CSRF 请求头，补齐后台令牌注入和用户端会话令牌引导；注销和试玩 Key 创建也检查 |
| 渠道 -1 不限额被校验抹成继承 | 保留限速、日限额、并发及冷却字段的 -1 语义 |
| 下游鉴权字段串到上游 | 使用账号密钥生成指定鉴权头，不复制客户凭据、Cookie 或任意请求头 |
| 自动重定向可能带走自定义 X-API-Key | 代理客户端禁止跟随重定向；不发起第二跳请求 |
| Base URL 与端点拼接被查询/片段/凭据污染 | URL 解析并拒绝凭据、查询、片段及控制字符；端点只允许固定协议列表 |
| 对话、旧版文本补全与向量失败共用负缓存和熔断 | 独立命名空间，并拒绝模型名控制字符，防止命名空间碰撞 |
| 切换渠道接口后旧错误仍阻塞新路由 | 路由改变时失效缓存；首次升级清理旧的未隔离状态 |
| 上游非流式/错误体无大小界限 | 解压后最多 20 MiB，超限即终止读取 |
| 无效 UTF-8 被替换字符后继续转发 | 明确拒绝，避免悄悄改变请求或响应内容 |
| `"stream":"false"` 按非空字符串变为 true | 明确解析布尔值和兼容字符串，拒绝其他类型 |
| 极端 usage 数值使加法溢出并可能污染锁 | 非负归一化、饱和加法及回归验证 |
| 缓存命中/写入 token 与普通输入 token 混用 | 统一内部统计并恢复原协议对应字段 |
| provider 只发工具 arguments.done 时参数丢失 | 无 delta 时使用 done 中完整参数，并避免重复追加 |
| 不支持的原生工具/历史被静默忽略 | 显式拒绝无法保持语义的内容与参数 |
| 慢响应头路径忘记使用原生协议转换 | 同一计划随异步请求移交，心跳后继续正确转换；断连回收 |
| 非流式空 choice 对象被当成功 | 成功/计费前要求有效 message 或 text |

## 后台 API 兼容性

后台与用户中心的状态修改请求现在必须携带 `X-CSRF`。仅发送 Cookie 的旧脚本需要同步更新；管理端令牌来自登录响应的 `csrf` 字段，用户端也可通过 `/api/user/session` 获取。网页前端已经更新，普通网页登录、保存与操作不需要额外配置。`/v1/*` 的 API Key 调用不受此规则影响。

## 验证范围

最终验证：Linux x86_64 / Rust 1.99.1，33 项测试通过、0 个失败、0 条编译警告。标准 Release 构建通过。实际二进制额外验证了后台控件与配置保存、用户中心 CSRF 拒绝和正常创建 Key、旧数据目录升级清理缓存，以及 SIGTERM 正常退出。

测试包括原有 16 项和新增协议、安全回归；完整 HTTP 测试覆盖四种下游 × 四种上游 × 流式/非流式的 32 组组合，并验证：

- 实际上游路径、请求字段与模型别名。
- 渠道凭据和鉴权头；客户凭据与 Cookie 不转发。
- 正确的下游 JSON 或终端事件；真实 usage 与一次成功计费。
- Embeddings 独立转发，异常断流不扣费。
- 重定向目标没有收到请求。
- 慢响应头提交心跳后的协议适配、客户端断连释放。
- 非法配置、畸形 JSON 参数、UTF-8、响应大小、极端 token 值及升级缓存迁移。

所有网络测试使用本地模拟服务，没有调用真实收费上游。Windows 工作流已保留，本次本地验证环境为 Linux；无法据此宣称所有厂商的非标准接口都已通过实测。最终命令结果见修复包 `VALIDATION.txt`。

## 协议边界

- 通用子集：文本、函数工具、Chat/Responses/Messages 图片输入、usage、结束原因。
- 旧版 Completions 不支持图片与工具；跨协议 prompt 使用文本角色标签，没有通用角色隔离能力。
- 不支持有状态 Responses 会话、后台任务、服务端内置工具、音频/文件、带签名的思考历史；这些功能需要原生代理方案，当前会拒绝无法转换的输入。
- 不能等价映射的参数会拒绝；不承诺把每个原生服务参数转换成另一个协议。
- 仍使用原项目 JSON 文件存储和既有计费产品规则；本次更新不等同于数据库事务改造或全部漏洞不存在的证明。
