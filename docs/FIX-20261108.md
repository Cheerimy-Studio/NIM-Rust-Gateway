# 1.7.59 增量修复说明

日期：2026-11-08（北京时间）

基线：Cheerimy-Studio/NIM-Rust-Gateway，提交 `841b0f8b8250c7c587bd12ec24d6057939746a3a`，原版本 1.7.58。

## 修复内容

| 范围 | 原问题 | 处理方式 |
| --- | --- | --- |
| 登录 | 限流发生在密码验证之后，超限仍能继续验证；密码计算占用请求线程 | 验证前按登录入口、来源和账号限制尝试次数；密码计算转入最多 4 个并行任务，繁忙时返回可重试错误 |
| 注册 | 验证码正确但密码不合规、注册关闭时，验证码仍被消耗 | 注册条件先校验，创建用户与消耗验证码在同一次存储更新完成；单个验证码最多允许 5 次错误尝试 |
| 密码重置 | 多条旧链接仍可依次使用；消费令牌与更新密码分两次执行 | 单次更新完成改密与令牌撤销；令牌绑定密码版本；登录会话使用已验证密码的版本，避免并发改密产生新会话 |
| 管理员重置用户密码 | 旧邮件重置链接仍可使用；持有存储锁计算密码 | 在锁外计算密码，同时撤销该用户的重置链接 |
| 模型可见性 | 模型广场可能显示隐藏原名或不可调用的别名 | 使用请求路由相同的渠道判断规则；忽略不可路由渠道的付费标记与健康统计 |
| 旧配置 | 导入循环模型路由后，可路由判断可能无限递归 | 不递归展开不支持的嵌套路由，保留普通成员判断 |
| 用户反馈 | Toast 缺少显示状态，操作提示被 Bootstrap 隐藏 | 显式显示提示，并增加辅助技术播报 |
| Key 管理 | 列表多出一列，删除使用浏览器原生确认框 | 修复列数；使用统一确认框，默认聚焦取消按钮，支持 Esc 与焦点恢复 |
| 队列状态 | 请求失败后仍展示旧状态，无法判断数据是否更新 | 显示更新时间、刷新按钮与失败提示；隐藏页面暂停轮询，避免重复请求 |
| 查询与日志 | URL 编码后的加号被误解为空格；极端时间戳倒序溢出 | 修正解码顺序；使用安全的倒序比较 |

## 界面与功能

- 首页、登录、管理端、用户中心、队列页和 WebClaw 共用浅色样式，统一导航、按钮、表单、表格和弹窗。
- 调整窄屏导航、间距与内容布局；支持系统的减少动画偏好。
- 模型广场新增名称搜索、免费/付费筛选、模型名称复制和对话测试入口。测试链接携带所选模型，并创建独立测试项目。
- 管理端与用户端刷新后保留当前栏目；用户端切换栏目时刷新对应内容。
- 登录、注册、密码重置与创建 Key 操作增加提交状态，避免重复点击。修复验证码发送中的倒计时提前解锁。
- 简化模型接入、思考参数和路由说明；将用户可见的“拉人活动”改为“邀请活动”。付费限速为 0 的说明修正为“不限”，与实际行为一致。
- Bootstrap、图标字体、marked 和 DOMPurify 随二进制内嵌，页面不再依赖外部 CDN。DOMPurify 更新为 3.4.17，许可与来源记录见 `web/vendor/README.md`。

## 应用与部署

补丁包是源码增量包，包含变更文件、Git 补丁、文件校验清单和应用脚本。未附 Windows 或 Linux 可执行文件。页面资源在编译时内嵌，因此需要重新编译，单独替换 web 目录不会改变正在运行的程序。

1. 使用包内 `apply_fix.py --target 仓库目录 --check` 检查文件基线。
2. 使用 `apply_fix.py --target 仓库目录 --apply` 应用。脚本先备份待修改的源码，发现文件冲突则停止，避免覆盖本地改动。
3. 在仓库目录执行 `cargo build --locked --release`，停止旧进程后替换二进制，再按原方式启动。
4. 构建 Windows 版本需在 Windows 执行同样的构建命令。需要兼容 glibc 2.17 的 Linux 包时，沿用仓库 Release 工作流中的 zigbuild 命令。
5. 使用已有数据目录启动，核对管理员登录、用户余额、Key、模型价格与签到抽奖记录。

应用脚本只处理清单内源码文件，不修改运行数据或自动发布 Release。上线前备份二进制和数据目录；回滚源码可使用脚本输出的备份路径。运行期间产生新数据后，回滚程序与恢复旧数据是两个独立操作，不应直接覆盖新数据。
