本轮主要处理请求转发、流式协议、调用计费判定、并发资源释放、日志迁移与备份，并删除编译器确认未被引用的实现。没有连接生产上游，也没有改动生产数据或推送远端分支。

## 已修复的问题

| 问题 | 原有影响 | 修复结果 |
|---|---|---|
| CRLF 在网络分块边界被拆开 | Responses / Anthropic 的 SSE 事件可能无法识别或丢失 | 共用按字节增量解析器，支持 LF、CRLF、CR、多行 data、BOM 和跨块 UTF-8 |
| 上游提前 EOF 被无条件 finalize | 半截回复可能变成成功终端事件，并触发扣费 | 完整 `[DONE]`，或全部 choice 已结束且没有残缺事件，才按正常结束处理 |
| HTTP 200 流内错误没有进入失败统计 | 故障账号仍被当作成功，用户可能被扣费 | 识别顶层 error，发出对应协议错误，记录失败且不扣费 |
| 按中英字符切换密度、特殊 token 示例或重复感叹号猜测异常 | 合法正文与推理内容被截断、清空，甚至重试 | 删除这类内容猜测和改写；保留协议与结构校验 |
| 流式 usage 被字节估算覆盖 | 上游提供真实 token 数时仍产生不准确统计 | 优先采用真实 usage；缺失时仅估算生成内容，不计算 SSE 包装字节 |
| 用正则替换 SSE 中的 model | 可能改到嵌套字段，别名中的引号或替换符可能破坏输出 | 解析完整 JSON 事件，仅改顶层 model，由 JSON 序列化转义，并保留 SSE 元数据 |
| 工具调用首片段名称重复追加 | 最终名称可能变为 weatherweather | 首片段只初始化一次，后续片段再追加 |
| Responses 最终 output 顺序按工具 index 排序 | 最终数组与已发送 output_index 不一致 | 按实际分配的 output_index 构建最终数组 |
| Responses 长度受限仍发 response.completed | SDK 收到互相矛盾的事件与状态 | 发出 response.incomplete；终态后忽略后续内容 |
| pump 任务没有完整的账号持有兜底 | 任务取消、未开始执行即被取消时可能泄漏在途计数 | 在启动任务前创建持有守卫；正常释放一次，取消路径由 Drop 释放 |
| 静默上游期间无法及时察觉下游断连 | 无效请求继续占用账号和连接 | 读取上游时同时监听下游关闭；慢启动路径也支持取消并限制错误体读取时间 |
| 排队上限检查与占位分开加锁 | 并发请求可能同时通过上限检查 | 检查并增加等待计数放在同一临界区 |
| 排队 deadline 截断后又乘随机抖动 | 实际等待可能超过配置上限 | 最终睡眠时间再次受剩余 deadline 限制 |
| 旧队列残留与统计中的过早过滤 | 重启后出现幽灵请求，冷却等待中的活跃请求又可能消失 | 启动清理失效队列；运行中由请求守卫移除活跃记录 |
| 非流式 HTTP 200 的 HTML、无效 JSON、空 choices 或错误对象仍可能记成功 | 错误回复可能触发计费 | 在成功统计和计费前校验 JSON 结构和顶层 error；Embeddings 校验 data |
| 首帧 error:null 与错误前缀的启发式识别 | 正常流可能被降级、重试或拒绝 | 只把非 null 错误对象作为错误；不依据不完整 JSON 前缀判错 |
| 环境变量修改管理员密码未轮换会话密钥 | 旧登录态可能仍有效 | 实际改密时同步轮换 session_secret |
| 短访问令牌遮罩函数返回原文 | 短令牌完整进入日志 | 非空短令牌输出遮罩 |
| 数据落盘忽略 sync_all 失败 | 写盘失败后仍可能把文件替换视作成功 | 将同步失败返回持久化流程，保留重试状态 |
| 更新备份只复制顶层文件 | db/signs 下的签到历史未被备份 | 递归复制目录，传播读取失败，跳过临时文件与符号链接 |
| 旧调用日志迁移按全站条数 truncate | 活跃用户日志可能挤掉其他用户的历史 | 合并、按时间排序后按每用户配置裁剪；支持 0 保留、幂等迁移与极端时间戳 |

## 回归验证

```bash
cargo test --locked --all-targets -j 2
cargo build --locked --release -j 2
```

实际验证环境：Linux x86_64，Rust 1.99.1。最终运行结果：16 个测试通过、0 个失败、0 条编译警告；标准 release 构建通过。发布二进制实际启动后，首页返回 HTTP 200，SIGTERM 退出码为 0。

单元与回归测试共 16 个。HTTP 综合测试包含三种协议各 5 类 pump 场景、下游取消、完整 Router 鉴权和三个公开协议入口。覆盖正常结束、缺失 `[DONE]` 但已有 finish_reason、提前断流、残缺 JSON、流内错误、真实 usage 与账本扣费、模型别名及 error:null。

测试不调用真实 NVIDIA NIM，不消耗上游余额。应用补丁后，仍应使用实际渠道进行少量集成验证，尤其是自定义上游的非标准 SSE。

## 行为边界与尚存设计债务

- 单个 SSE 事件上限 1 MiB；不是整个回复上限。超大工具参数若全部集中在一个事件会被明确拒绝。
- 对不发送结束标记或 finish_reason 的上游，EOF 现在按异常处理；不再把网络关闭猜作成功。
- 缺失 usage 时仍然只能估算 token，不能替代上游 tokenizer。
- 排队仍使用竞争式轮询，不承诺严格 FIFO；本轮修正了容量与时间边界，没有重写整个调度器。
- 数据库仍是多份 JSON 文件和全库快照克隆；递归备份修复不等同于跨表事务或在线一致性快照。
- 原项目允许并发请求产生有账可查的欠款，余额预检不等同于额度预留；本轮保留现有产品规则。
- Chat 与转换端点仍存在重复的重试流程；本轮统一了流式解析与 pump，没有一次性重构全部路由循环。

这些边界表示本次修复的实际范围，不能据此声称全项目已不存在其他 BUG。
