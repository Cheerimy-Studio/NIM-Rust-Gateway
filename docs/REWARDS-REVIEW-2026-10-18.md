## 修复内容

| 问题 | 处理 |
| --- | --- |
| 签到记录先写独立文件、钱包后延迟落盘，异常退出可能少发奖励 | 新签到标记、赠金和流水一起提交；旧每日文件只读兼容 |
| 旧签到文件读取失败被当作空记录 | 文件损坏或无权限时拒绝签到，不重置已有记录 |
| 签到资格和开关在锁外预读，停用与签到存在竞态 | 在同一事务内读取当前开关并验证用户启用状态 |
| 连点、跨午夜、关闭签到后的按钮状态不及时更新 | 前端请求互斥、结束后刷新状态、按服务端午夜倒计时刷新，关闭时隐藏入口 |
| 签到金额配置反转、非有限值或过小值仍能保存 | 普通保存和配置导入共同校验范围及 min/max 顺序 |
| 抽奖先预选一次、加锁后又选一次，校验与逻辑重复 | 在事务内读取当前活动并只选一次；扣费、奖品、日志与抵扣次数共享同一快照 |
| 跨 users/wheels/promo 表只在内存中完成，没有崩溃一致性 | 先同步奖励事务日志，再写回分表；启动先恢复已提交日志 |
| 分表写回失败后又有普通更新，恢复可能覆盖后续余额 | 每次重试写回前推进事务日志；写盘失败时保留有效内存快照 |
| 网络重试或重复点击造成多次扣费 | 前端互斥并保存请求 ID；服务端按用户返回原回执，包含原奖品 Key |
| 回执过期或被容量上限清理后，旧请求可能被当作新抽奖 | 带请求时间的过期请求拒绝执行，记录归档边界阻止已清理请求再次扣费 |
| 看到旧价格时后台已改价，仍按新价格扣费 | 网页发送 expected_cost，不一致则拒绝并刷新活动 |
| 奖项在后台变化后，动画沿用旧列表停错格 | 服务端返回本次实际活动快照，动画按该快照定位并保留最终落点 |
| 展示权重被当作实际中奖概率，和抽取概率不符 | 扇区大小沿用展示权重；概率表显示由抽取权重计算的实际概率，不暴露原始权重 |
| 展示概率舍入后小扇区消失 | 几何占比保留精度，概率文本独立格式化 |
| 所有抽取权重为零、微小金额量化成零、非法奖品仍可保存 | 保存和执行时校验有效奖项、非有限数字、范围、ID 唯一性和量化后金额 |
| 次数允许小数，体验卡残留旧 quota 导致被错误限次 | 专属次数只允许正整数，体验卡清除旧 quota，鉴权按奖品类型判断 |
| 时长过大导致有效期整数溢出，过小时长立即失效 | 时长范围校验、至少一秒、checked_add 计算到期时间 |
| 模型名被截断，或者合法纯数字模型名被拒绝 | 保留完整模型名并验证长度和控制字符，允许数字模型标识 |
| 并发调用只检查 used，剩余一次可能同时执行多次 | 同一锁内校验当前用户、有效期、并发及 used+在途预留；失败释放，成功消耗 |
| 奖品成功调用的次数没有及时持久化 | 计数走奖励事务；提交失败时暂停该 Key，避免继续使用未记下的额度 |
| 翻倍奖到账两份但结果只显示一份；抵扣抽奖仍记录原价 | 结果返回实际到账总额；日志记录实际支付及抵扣标志 |
| 切换奖品类型丢失正在编辑的金额/模型，新行显示错误占位 | 分别保留两类输入，按类型启用适用字段，保存按钮防重复提交 |
| 已删除活动被旧编辑页重新保存后复活 | 不存在的编辑 ID 拒绝保存；删除和奖品 Key 停用同步提交 |
| 全局抽奖日志截断让活跃用户挤掉其他人的全部记录 | 每位用户独立保留最近 50 条 |
| JSON 临时文件在收紧权限前可能短暂可读 | Unix 创建时使用 0600，写入后同步文件内容 |

## 新请求字段与兼容性

`POST /api/user/wheels/draw` 的网页请求自动包含：

- `request_id`：本次操作的随机 ID，重试保持不变。
- `requested_at`：活动接口返回的 `server_time`，重试保持原值，避免依赖浏览器时钟。
- `expected_cost`：确认框对应的活动单次费用。

同一用户的相同 ID 在回执保留期内返回同一结果。回执保留最近 24 小时内最多 100 条。携带原请求时间时，过期或已归档请求会拒绝重新抽取，应先查看个人记录；需要发起新抽奖时刷新活动并使用新 ID。旧调用方不传这些字段仍可调用，但缺少完整的重试与价格确认保护。

奖项配置上限：单次费用及单个余额奖品 10 亿元，专属次数 10 亿次，并发 1 至 64，有效期最多 876000 小时；金额精度为 0.000001 元。旧配置中不合理的超限值需要先编辑后再启用，执行时同样校验，校验失败不扣费。

`/api/user/sign` 状态增加 `day` 和 `reset_in`，日期仍按服务进程本地时区计算。需要北京时间时配置 `TZ=Asia/Shanghai`。旧 `db/signs/sign_YYYY-MM-DD.json` 不会删除；新签到写入用户行的 `last_sign_day` / `last_sign_amount`，与赠金同事务提交。

升级后不要直接换回不识别这些字段的旧二进制；需要回退时还原升级前的完整数据备份。JSON 存储仍按单进程运行设计，不支持多个网关进程同时共享同一数据目录。事务日志损坏时停止恢复，需先修复存储，不会以部分财务数据继续启动。
